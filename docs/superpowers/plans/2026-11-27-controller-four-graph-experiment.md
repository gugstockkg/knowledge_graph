# 최대주주 변경 네 그래프 조건 실험 계획서

**목표** — 금호에이치티와 여러 상장사를 한 평가 세트에 넣어, LPG와 RDF/OWL의 결합이 질문에 대한 답, 원문 근거, 조회 비용에 어떤 영향을 주는지 측정한다.

**실행 환경** — EC2의 격리된 Neo4j, Cypher, RDFLib, OWL-RL 및 SPARQL. 기존 단일 사례 실행 코드를 여러 사건으로 확장한다.

**설계 기준** — [최대주주 변경 온톨로지](../../../ontology/controller-change-v0.1/README.md), [기존 EC2 검증](../../research/control_ownership_ec2_validation.md), [S3 공시군 추출](../../research/opendart_s3_inventory.md).

## 표본 선정과 원문 정답

- 모집단은 기존 EC2 스냅샷의 최대주주 변경 원공시 179건, 163개 회사다. 접수일 범위는 2026-01-02~11-26이다. 주식양수도 34쌍, 임원·주요주주 18쌍, 정기보고서 190쌍의 연결 후보도 검수에 사용한다.
- **목표는 금호에이치티를 포함한 독립 사건 30개와 질문 약 90개**다. 합병·분할, 계약 이행, 증여·상속, 증자, 연결 보류·근거 부족 사례를 포함한다. 적격 사건이 부족한 유형은 실제 분모와 부족 사유를 보고한다.
- **큰 회사 우선**의 기준은 공시 접수일 직전 거래일의 시가총액이다. 종목코드와 날짜를 KRX 시가총액 자료에 매핑하고, 사건 유형별 할당 안에서 큰 회사를 우선한다. 조회되지 않은 값은 미확인으로 남긴다. 이번 계획에서는 후보의 시가총액 순위를 아직 확인하지 않았다.
- **금호에이치티를 다른 회사와 동일한 실행·동일한 채점에 넣는다.** 전체 결과를 먼저 보고하고, 기존 파일럿과 규칙 개발에 쓴 사례를 제외한 수치도 함께 산출한다.
- 한화비전과 한화갤러리아처럼 한 사건이 여러 회사의 변경을 일으킨 경우, 회사별 답은 각각 채점하고 통계에서는 같은 원인 사건 군집으로 묶는다.
- 정답은 추출 결과와 별도로 원문에서 두 차례 대조한다. 질문 ID, 사건 ID, 원인 사건 군집, 기준일, 답의 상태와 필드, 필수 근거를 고정한 뒤 결과를 실행한다. 근거는 접수번호·원문 SHA-256·XML 행 또는 표 좌표까지 기록한다.

## 네 조건

| 조건 | 입력과 조회 |
|---|---|
| ① LPG만 | 정정 이력·시점별 주장·원문 근거를 Neo4j에서 Cypher로 조회 |
| ② RDF/OWL만 | 사건 유형·참여 역할·유형 근거를 RDF에서 OWL-RL 및 SPARQL로 조회 |
| ③ LPG + RDF/OWL | ①의 시점별 값과 ②의 유형 판정을 공통 사건 ID로 조인 |
| ④ 동일 지식 단일 LPG | ③이 가진 두 쪽의 명시적 사실·근거를 단일 Neo4j에 넣고 동등한 유형·시간 규칙을 Cypher에서 적용 |

①·②에 어떤 사실을 제공했는지 공개하고 각 조건에서 반환한 부분 답도 채점한다. ③·④에는 같은 원문 버전, 사건 ID, 주장, 근거와 동등한 시점·분류 규칙을 적용한다. 합병과 인적분할이 기업구조재편에 속한다는 귀결이 양쪽에서 같은지 검사한다. **③ 대 ①·②는 상보성**, **③ 대 ④는 지식과 규칙을 고정했을 때 그래프를 분리해 조회하는 효과**를 측정한다.

## 실행 체크리스트

### 1. 표본과 정답을 고정한다

- [ ] EC2 산출물 improved-final.json과 linked-ownership.json에서 사례를 선별하고 시가총액 자료를 대조한다. 회사·유형·원인 사건 군집·기존 검수 여부와 원문 해시를 cases.json에 기록한다.
- [ ] 원공시와 정정의 대상, 시점, 집계 범위를 읽고, 추가 공시는 계약 이행 증거인지 보유 상태 관측인지 구분한다.
- [ ] 진입점의 입력으로 cases.json과 gold.jsonl을 확정한다. gold.jsonl에는 question_id, event_id, cluster_id, cutoff, expected_status, expected_fields, required_evidence를 넣는다.
- [ ] 금호에이치티의 정정 전 52.25%와 정정 후 52.39%, 보고된 변경일 10월 27일, 각각의 원문 근거가 포함됐는지 확인한다.

### 2. 네 구현을 같은 사건 세트로 실행한다

- [ ] 기존 scripts/compare_controller_graphs.py가 cases.json과 gold.jsonl을 읽도록 확장한다. 출력은 질문 ID, 조건, 답, 상태, 근거 ID, 반복별 지연을 포함한다.
- [ ] tests/unit/test_controller_experiment.py에서 미래 정정값 누출, 개인과 보고집단 혼동, 계약 체결을 완료로 판단하는 경우, 비해당 사건 유형, 같은 원인 사건의 여러 회사 사례를 검사한다.
- [ ] 운영 그래프와 분리된 EC2 실험 DB를 사용한다. ③·④의 원천 사실·필드와 유형 귀결이 같은지 대조하고, 차이는 근거와 규칙 단위로 진단한다.
- [ ] 확정 질문마다 네 조건을 모두 실행해 answers.jsonl에 저장한다. 준비 실행 후 질의별 최소 5회 반복하고, 고정 시드로 조건 순서를 섞는다. 그래프 구축·추론 전처리와 질의 시간은 따로 기록한다.

### 3. 결과를 함께 보고한다

- [ ] 1차 지표는 **모든 정답 필드와 필수 원문 근거가 맞은 질문의 비율**이다. 보조 지표는 필드 F1, 필수 근거 재현율, 시점 위반, 보류 정확도다.
- [ ] 같은 질문에 대한 조건별 차이를 계산한다. 신뢰구간은 원인 사건 군집 단위로 재표집하고, 질문 유형별 분모와 독립 사건 수를 제시한다.
- [ ] ③·④의 조회 지연 p50·p95, 추론·적재 비용, 조인 시간을 별도로 기록한다. 답과 근거가 같으면 동등하게 관측됐다고 보고 비용 차이를 해석한다.
- [ ] 금호에이치티를 포함한 전체 표와 이미 검수한 사례를 제외한 결과를 docs/research/controller_four_graph_results.md에 기록한다. 정답·근거 불일치 목록과 EC2 재현 경로를 포함한다.

금호에이치티를 포함한 여러 회사가 같은 네 조건에서 채점되고, 질문별 원문 근거와 정답을 다시 확인할 수 있다. 표본의 실제 시가총액 범위와 사건 구성, ③ 대 단독 조건, ③ 대 ④의 답·근거·조회 비용이 한 결과 보고서에 들어간다.

## 검증 계약과 갱신 실험

아래는 본실험의 추가 완료 기준이다. 앞의 네 조건과 사건 표본을 유지한다. TRACE 예측과 LLM 가드레일은 각각 별도 실험으로 실행하고 결과표를 나눈다.

### 4. CQ에 필요한 최소 모델과 공통 응답

- [ ] 금호에이치티의 원본·정정, 한화 인적분할, 체결만 확인된 주식양수도, 미정의 관계에서 각각 한 CQ를 먼저 재현한다. 같은 원문으로 회사·증권·사건·주장·근거를 그려보고, 사람이 질문별 필수 조건을 검수한다. LLM이 초안을 제안하는 경우에도 정답과 제약의 확정은 사람이 담당한다.
- [ ] 공통 응답에는 사건 ID, 기업 ID, 해당 시 증권 ID, 후보·채택 여부, 기준일, 상태, 답 필드, 적용 및 미검사 조건, 출처와 추론에 사용한 공리 버전을 넣는다. 기업, 상장증권, 경제 사건 ID를 따로 유지하고, 등가 자료의 근거 집합은 정렬한 뒤 ③·④에서 비교한다.
- [ ] RDF의 원천 기록은 공시가 제시한 주장과 그 근거를 명시한다. 예를 들어 계약 체결 공시의 존재와 거래 완료 확인을 구분한다. 근거 성격은 주장에 속성으로 두고, 여러 출처나 별도 시간·역할·방법·버전 정보가 있으면 근거 노드로 둔다. 직접 입증에 필요한 근거 유형을 통과한 후보에만 점수나 가중치를 적용한다.
- [ ] 시맨틱 레이어는 버전이 있는 매핑으로 기업코드·증권 ID·사건 ID를 연결한다. 종목코드 변경, 보통주와 우선주의 혼합, ID가 불확실한 경우를 각각 회귀 검증한다. 같은 회사를 가리키는 문자열만으로 조인하지 않는다.

### 5. 의미·형식·근거·시점 검증

| 사례 | 기대 결과 |
|---|---|
| 흡수합병이 보고되고 상위 유형이 생략됨 | 기존 공리로 상위 유형을 도출하고 원문과 공리를 반환 |
| 완료 근거 없이 체결만 보고됨 | 완료 여부에 근거 부족을 반환 |
| 새 거래 관계가 기존 어휘에 없음 | 원문 표현·출처를 미분류 후보로 보존 |
| 보고 범위나 출처가 충돌함 | 충돌 상태와 양쪽 근거를 반환 |
| 질의 도구가 특정 조건을 검사하지 않음 | 검사하지 않은 조건을 응답에 명시 |
| 10월 28일 질의에서 다음 날 정정본을 인용함 | 자료형·필수 필드가 맞아도 시점 검증 실패 |

- [ ] 원천 RDF에는 식별자·출처·공시 주장에 관한 SHACL을 적용하고, OWL-RL 추론 후에는 추론된 타입이나 필수 관계가 걸린 Shape를 별도로 검사한다. 그래프 버전, 추론 프로파일, Shape 버전, 검증 대상과 결과를 기록한다. OWL의 열린 세계 가정은 미확인 사실을 거짓으로 바꾸지 않으며, SHACL의 필수 필드 요구는 확정 답변을 제출할 때 적용한다.
- [ ] 수치·단위·범위가 인용한 원문 셀과 같은지, 해당 근거가 거래 완료를 입증하는지, 기준일까지 공개됐는지는 원문 대조와 시점 질의로 검증한다. SHACL 형식 검사 통과와 원문 정확도를 별도 점수로 낸다.
- [ ] 임시 그래프에 정정 추가, 공리 삭제·복원, RDF 내보내기·재가져오기를 적용한다. 각각 재계산된 결과와 기존 추론 캐시의 결과, ID·URI 보존 여부를 대조한다. 정정 이전 답은 그대로 유지돼야 하고 공리 제거로 파생 타입이 사라져도 원천 공시 값은 보존돼야 한다.
- [ ] 운영 지표는 필수 근거까지 역추적 가능한 필드 비율, 미분류율, 정정 입수부터 질의 반영까지의 시간, 재추론·재검증 소요 시간이다. 인증·인가, 조인·캐시의 권한 유지 여부는 공개 원문 PoC와 별도 운영 테스트로 확인한다.

### 6. LLM 가드레일과 저장 구조 후속 비교

- [ ] 그래프 본실험을 마친 뒤 같은 질문과 같은 모델·검색 입력으로 구조화된 답변을 생성한다. 가드레일 적용 전후에 근거 없는 단정률, 올바른 보류율, 과잉 보류율, 정답과 근거 정확도, 검사 비용을 비교한다. 답변을 RDF로 변환한 뒤 SHACL과 원문·시점 검사를 적용하고, LLM 설명은 검증 보고서의 근거에만 의존하도록 한다.
- [ ] 검증된 원천 기록을 RDF에, 적용 기간이 있는 분석 의견을 Temporal LPG에 적재하는 운영 구조는 별도 가설로 검증한다. 의견에는 작성 당시 가용 시점, 적용 시작·종료, 근거, 작성자 또는 모델 버전, 만료·철회를 기록한다. 동일한 의견과 유효기간 규칙을 담은 단일 저장소와 비교해 정확도와 갱신 비용을 측정한다. 이 비교는 현재 ①~④의 저장 모델 차이에 의견 유무가 섞이지 않도록 분리한다.

### 연구 근거

- OWL과 SHACL을 함께 쓸 때 어떤 그래프와 의미론으로 검증하는지 고정하는 근거다. 이 PoC는 원천과 OWL-RL 결과를 별도로 검사하며 논문의 일반 재작성 기법을 구현한 것으로 해석하지 않는다. [Oudshoorn et al. (2026)](https://repositum.tuwien.at/handle/20.500.12708/230858) · [W3C SHACL](https://www.w3.org/TR/shacl/)
- 업데이트 전후의 제약 유지와 검증 리포트의 근거 추적에 각각 적용한다. 설명을 캐시할 때는 Shape·자료·추론 버전을 키에 포함한다. [Ahmetaj et al. (2025)](https://arxiv.org/abs/2508.00137) · [Publio & Labra Gayo (2025)](https://arxiv.org/abs/2507.08432)
- LLM이 제안한 제약은 어휘와 의미를 사람이 대조한 뒤 반영한다. 컴파일 성공과 규칙 의미의 정확성을 구분한다. [Kaewsawee et al. (2026), 프리프린트](https://arxiv.org/abs/2608.09028)

주가 예측으로 연결하는 후속 가설과 검증 순서는 [TRACE 고도화 설계](../../research/trace_ontology_followup.md)에 있다.
