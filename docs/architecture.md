# 파이프라인 구성

`ingestion`은 OpenDART API·재시도·캐시와 원본 저장, `extraction`은 DART 필드 표식과 위치 읽기, `graph`는 원본 v0.1에 따른 노드·관계·근거 생성, `storage`는 Neo4j 형식 변환·적재·조회 검증을 담당합니다. `scripts/kg.py` 또는 설치 후 `kg`가 이 단계들을 호출합니다.

`config.get_paths()`가 데이터·출력·런타임·비밀정보 루트를 관리합니다. 코드에서 특정 사용자의 홈을 전제하지 않으며, EC2는 환경변수로 EBS 경로를 지정합니다. 현재 파일럿의 온톨로지 버전은 v0.1로 제한됩니다.

원문은 `data/raw`, 파생 그래프는 `data/graph`, 실제 DB는 `data/neo4j`에 둡니다. 결과와 이전 검증 기록은 artifacts로 분리합니다. 이 네 영역과 인증정보·실행 바이너리는 Git에서 제외됩니다. 코드와 데이터의 변경 주기를 분리하는 구조입니다.

이전 과정에서는 원문 바이트와 SHA256을 보존했고, 파생 결과는 새 경로로 재생성했습니다. v0.1 ID·경제 값·시간·범위·근거 위치를 이전 결과와 비교했습니다. 파일 경로가 바뀌므로 파생 노드 CSV 전체 해시는 달라질 수 있습니다.

Neo4j는 GUGPilot의 전역 ID 유일성 제약과 원본 도메인 라벨을 사용합니다. 관계 ID를 MERGE하여 재적재 중복을 막으며, 삭제 동기화나 전체 최신 상태 재계산은 아직 지원하지 않습니다. 기존 파일이 없어졌다고 DB 객체를 자동 삭제하지 않습니다.

Mac 로컬 실행은 프로젝트 전용 Java와 native 서버, EC2는 버전 고정 Community 이미지로 실행합니다. DB 조회 코드는 공통 HTTP Query API를 사용합니다. Compose의 호스트 포트는 localhost에만 공개합니다.
