# 한국 일별 주가와 공시 KG 연결

## 이번 범위

기존 공시 파일럿의 5개 기업(096690·351320·490470·214330·457600)에 대해 2026-09-01~11-05 일별 OHLCV를 수집했다. 각 44개, 총 220개 관측이다. 당일 미완성 일봉을 피하기 위해 수집 종료일은 한국 시간 기준 전일까지로 제한한다.

KRX·공공데이터 인증키가 설정되어 있지 않아 네이버 공개 차트의 일별 관측을 사용했다. FinanceDataReader의 공식 소스에서 사용 중인 공개 경로를 참고했으며 별도 라이브러리 설치는 필요 없다.

- 참고: https://github.com/FinanceData/FinanceDataReader/blob/master/src/FinanceDataReader/naver/data.py
- 실제 출처 URL·조회 시각·원문 SHA256은 각 데이터셋 manifest에 기록한다.
- 현재 수집한 원본 스냅샷은 과거 특정일에 공개된 가격 데이터의 빈티지 스냅샷이 아니다.
- 데이터 이용·재배포 권한은 라이브러리 코드 라이선스와 별개다. 원문·가격·수익률 결과는 Git 제외 경로에 보존한다.

## 실행

```bash
python3 scripts/kg.py prices --start 2026-09-01 --end 2026-11-05
python3 scripts/kg.py market-link
```

같은 구간은 로컬 캐시를 재사용하며 새 스냅샷이 필요할 때 --refresh를 붙인다. 기본 연동 구간은 위 날짜다. 다른 구간을 수집한 경우 `market-link --dataset 데이터셋경로`를 지정한다.

데이터: `data/market/naver_daily/20260901_20261105/`
- raw: 제공 응답·조회 메타데이터.
- prices.csv / manifest.json: 필터링된 OHLCV·검증·종목명 매핑·스냅샷 버전.
- event_returns.csv: 20개 공시 × 1/5/20개 관측 일봉 구간, 총 60개 평가 행. 결측은 0으로 채우지 않는다.
- neo4j_import.json: 적재 건수·원본 그래프 보존 검증.

## 그래프

기존 v0.1의 Security, PriceObservation, ISSUED_BY, PRICE_OF를 사용한다.

`Company <- ISSUED_BY - Security <- PRICE_OF - PriceObservation`

MarketPilot은 범위 표시 라벨이다. 공시 그래프 GUGPilot은 332개 노드·600개 내부 관계 그대로 보존한다. 증권 5개·가격 관측 220개와 관계 225개를 추가하여 첫 스냅샷 전체는 557개 노드·825개 관계가 된다.

종목코드와 제공 종목명을 공시의 기업명과 대조한 경우만 연결한다. ISIN이나 법적 증권 종류를 검증한 것은 아니며 Security ID는 네이버 종목코드 범위의 임시 식별자다. 이름 변경·코드 재사용·상장 종류 변경은 별도 시점별 기업행위 확인이 필요하다.

가격 관측은 데이터셋 버전을 포함한 ID를 사용한다. 같은 스냅샷 재적재는 중복을 만들지 않는다. 새 스냅샷은 별도 관측으로 보존하고 같은 소스·수집 종목의 기존 스냅샷을 active=false로 바꾼다. 조회는 active=true를 사용한다. 수정주가 여부는 확인되지 않아 adjusted=true/false를 추측하지 않고 adjustment_status=provider_adjustment_unverified로 기록한다.

## 공시 이후 수익률 해석

정확한 공시 공개 시각이 없어 공시 접수일 당일 체결을 가정하지 않는다. 접수일 이후 첫 제공 일봉의 시가를 시작값으로 하고, 1/5/20번째 제공 일봉의 종가와 비교한다. 기준일이 과거인 정정 공시도 접수일을 기준으로 평가한다.

수익률(%) = (해당 구간 마지막 종가 / 공시 다음 관측 거래일 시가 - 1) × 100.

첫 진입 일봉이 거래량 0 또는 시가 0이면 다음 날짜로 조용히 건너뛰지 않고 거래 불가로 표시한다. 청산일 거래 불가도 결측 처리한다. 필요한 미래 일봉이 충분하지 않으면 insufficient_future_bars로 표시한다. 제공 일봉 배열을 거래일 순서로 사용하며 독립적인 KRX 거래일 달력과 대조한 것은 아니다.

이는 **탐색용 사건 이후 가격 변화**다. 상승 예측값·인과효과·매매전략 성과가 아니다. 정정·합산 범위·지분 변동 원인, 액면분할/병합·권리락·수정주가, 거래정지·상장변경, 비용·시장수익률·선택 편향을 검토하기 전 예측 신호로 확정할 수 없다.

## 조회

`queries/market_examples.cypher`:
1. 금호에이치티와 연결된 증권·특정 일자 가격 그래프.

3. 공시 → 근거 → 보유현황 → 기업 → 증권 → 가격을 잇는 경로.

다음 단계는 공식 일별 시세·기업행위/수정주가·거래일 자료 대조와 시간 순서 평가셋 구성이다. 현재 예측 모델은 학습하지 않았다.

## 평가 단위 주의

같은 기업·접수일에 여러 공시가 있으면 같은 가격 구간이 여러 행에 반복됩니다. 현재 60행을 서로 독립적인 학습 표본 60개로 보아서는 안 됩니다. 학습 단계에서는 기업·사건일 기준 묶음과 시간 순서 분할, 겹치는 수익률 구간의 누출 방지를 설계해야 합니다. 사용자 지정 가격 구간을 쓰는 경우에는 공시 직후 가격이 실제 구간에 포함되는지 확인해야 하며, 이 예제는 2026-09-01~11-05 구간에 대해 검증했습니다.
