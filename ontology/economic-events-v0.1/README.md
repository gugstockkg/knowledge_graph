# FINTOS 경제 사건 온톨로지 v0.1

공시에서 공급계약·시설투자·실적 관측을 추출해 계약 당사자, 제품군, 시설투자와 재무를 기업에 연결한다. 코스피·코스닥·코넥스 공시를 유형별로 살피며, 삼성전자·SK하이닉스는 경로를 확인할 예시로 사용한다. [CSV 정의서](ontology.csv) · [질문 후보와 공시 인벤토리](../../docs/research/opendart_competency_questions.md)

## 역량 질문과 필요한 사실

| 질문 | 필요한 객체·관계 | 확인할 조건 |
| --- | --- | --- |
| CQ1. 누가 누구에게 무엇을 공급하기로 했는가? | 공급자·구매자 역할, 공급계약, 제품군 | 불명확한 상대는 연결을 보류한다. 공급자와 공시 제출인이 같은지 확인한다. |
| CQ2. 금액과 규모를 계산할 수 있는가? | 계약 조건 관측, 공급자 공시 매출 대비 비율, 회계기간별 재무값 | 금액, 통화, 단위, 보고 시점과 분모를 보존한다. |
| CQ3. 한 기업의 시설투자와 공급 계약은 어떻게 함께 조회되는가? | 기업의 시설투자 발표와 같은 기업의 구매계약 | 공시가 특정 시설을 명시한 경우에만 계약과 시설을 직접 연결한다. |
| CQ4. 어떤 정보가 그날까지 공개됐는가? | 원계약, 정정 조건 관측, 재무 공개 버전 | 미래 공시를 걸러내고 같은 날의 순서를 확인하지 못하면 충돌을 보존한다. |
| CQ5. 이 정보는 주가 방향에 추가 정보를 주는가? | 기업과 발행 증권의 시점별 연결, 거래일, 가격 관측 | 가격 기준선과 사건 조건을 맞춘다. 미래 수익률은 평가 데이터로 분리한다. |

## 정합성을 확인하는 방법

1. **개념 정합성.** FIBO의 계약·참여 역할·법인·증권 구분을 참고했다. 공급계약 서류는 거래의 근거이며 실제 계약의 역할은 당사자로 식별한다. CSV가 개념의 명세이고 Neo4j LPG가 구현 형식이다. [프로젝트 FIBO 검토](../alignment/fibo/FIBO_review.md)
2. **식별 정합성.** 기업은 OpenDART 기업 코드, 개별 증권은 시점별 종목 식별로 연결한다. 공시 제출 기업의 자회사가 계약 당사자인 경우 원문을 확인하기 전에는 모회사 역할로 적재하지 않는다.
3. **시점 정합성.** 접수일, 계약·투자 기간, 재무 회계기간을 따로 기록한다. 발표·계획·완료 상태는 근거가 확인된 범위에서 표현한다.
4. **수치 정합성.** 억원·백만원·조원의 단위를 원문에서 확인하고, 원문 표기와 환산값을 함께 보존한다. 공시된 공급자 매출 비율과 외부 재무 수치의 재계산값을 구분한다.
5. **구현 정합성.** Neo4j에서 관계의 출발·도착 라벨, 공시 연결, 가동 중 재적재 중복, 기준일 경계를 검사한다. 탐색 질의는 실제 공급계약과 관련 투자 발표를 같은 기업에서 보여준다. 확정 정정과 불명확 정정을 구분하는 평가셋은 별도로 검수한다.

## 적용 범위

기존 공시 카탈로그의 기업·공시 노드를 재사용한다. 시설투자와 실적의 도메인 항목은 원문을 읽고 값을 확인한 뒤 보강한다. 운영 중인 카탈로그의 전체 규모와 이 서브그래프의 적재 결과는 각 범위에 맞춰 집계한다. SHACL 검사는 RDF 내보내기가 필요한 후속 검증으로 둔다.
